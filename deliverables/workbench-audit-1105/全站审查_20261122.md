## 1. P0 真缺陷（8 条，均已复现）

### P0-1 发布门禁对「重复内联块」完全无分辨力，白屏版本能全绿发布 ✅复现

- **位置**：`_shared/inject_shared.py:111`（`pat.sub(..., count=1)`）、`_shared/verify_release.py:113-119`（只 `re.search` 首个块）
- **复现**：把 `任务管理台.html` 的 SHARED 块复制成两份（模拟合并冲突/误粘贴），`index.html` 同步，跑 `verify_release.py` → **0 项失败，25/25 PASS**。
- **后果**：文件里出现 2 个 `const CFG_DAY_MS`、2 个 `const PAGE_SIZE`（实测计数均为 2），同一 `<script>` 内重复顶层 `const` → `SyntaxError` → 整页脚本不执行，只剩静态骨架。再跑一次注入器也清不掉（`count=1` 只换第一份）。
- **改法**：注入前断言每页 `count(BEGIN)==1 and count(END)==1`，否则直接退出非零；门禁把「只数 MODAL-A11Y」升级为「5 个块 × 8 页逐个计数」。源文件里都不含标记串，不会误伤。
- **风险**：只加断言，不动块内容，不影响「逐字节一致」；当前各页计数均为 1，不会立刻报红。

### P0-2 门禁 `--repo` 只换产物目录、源文件永远读脚本自身目录 → 校验别的副本必然假绿 ✅复现

- **位置**：`_shared/verify_release.py:29-30`（`HERE`/`PROJ`）、`:33`（`REPO` 可覆盖）、`:103-108`（`src_path=os.path.join(HERE, srcname)`）
- **复现**：用 `tools-site/_shared/verify_release.py --repo ".../Obsidian Vault/Projects"` → **25/25 全 PASS**；改用 `Projects/` 自己的同一份脚本跑同一目录 → **3 项 FAIL**（TIMELINE-CORE 在 `时间线.html` / `home.html` 各 11458B vs 9169B，总数 23/25）。
- **后果**：这条正好掩盖了 P0-3。任何「用 A 的源比 B 的产物」都会比出假绿，是「改坏了也通过」的样板。
- **改法**：`src_path = os.path.join(REPO, "_shared", srcname)`；`TOKENS` 同理优先取 `REPO` 内副本。两者不同源时直接报错，禁止混比。
- **风险**：修好后 `--repo Projects` 会立刻报红（本来就该红）；`check.sh` 的常规调用（`REPO == tools-site`）行为不变。

### P0-3 阅读副本 `Projects/` 已落后：`sw.js` 还是 v26、`timeline-core.js` 是旧版（三处不再逐字节一致）✅复现

- **实测**：`Projects/sw.js` = `wb-app-v26`（发布仓库与 pc-app 都是 v28）；`Projects/_shared/timeline-core.js` MD5 `fa8ae58…` ≠ 仓库 `e91d093…`（10.6KB vs 13.5KB）。八页 HTML 本身一致。
- **后果**：`inject_shared.py` 是「按源文件整块替换」，一旦有人在 `Projects/` 下跑一次注入，就会把 v26 的 timeline-core 覆盖回 `时间线.html` 与 `home.html`，而 `run_regression.py --check-mirror` **只比 tools-site ↔ pc-app，不覆盖 Projects**，没人会发现。
- **改法**：把 `Projects/` 纳入镜像校验；同步两个文件后，副本自带 verify 必须 0 项失败（注意别用 P0-2 那条假绿路径去「验证」）。

### P0-4 明信片「本地备份」面板永远打不开，整块功能不可达 ✅复现

- **位置**：`明信片追踪.html:1139`（`<div class="dtab-panel" data-dtab="local" style="display:none;">`）、`:4625`（`p.hidden = p.dataset.dtab!==tab`）、`:154`（`.dtab-panel[hidden]{display:none!important}`）
- **现象**：JS 只切 `hidden` 属性，但内联 `style="display:none"` 优先级更高且永远不会被移除 → 切到「本地备份」后云同步面板被隐藏、本地面板仍隐藏 → 弹窗主体**整块空白**，导出 JSON / 导入恢复两个按钮永远看不到。
- **改法**：删掉第 1139 行的内联 `style="display:none;"`，初始态改由 HTML `hidden` 属性表达，让 JS 的 `p.hidden` 成为唯一开关。
- **风险**：低。删后若 JS 未执行会两个面板同显，用初始 `hidden` 兜底即可。

### P0-5 观剧删除带照片的记录抛 `ReferenceError`，删除完全失效 ✅复现

- **位置**：`观剧记录.html:655`（`Promise.all(ids.map(id=>idbGet(id)))`）；本页只定义了 `idbAll`/`idbPut`/`idbDel`（`:296-298`），**全页无 `idbGet`**
- **现象**：只要记录带照片，`ids` 非空 → async 回调内同步抛错 → 后续 `then` 全不执行。用户确认删除后无任何反馈、记录仍在、照片未删、控制台报错；只有「无照片记录」能删，8 秒撤销也永远走不到。
- **改法**：补一个 `idbGet(k)`（可照抄 `旅行地图.html:892-897`），或删除前 `idbAll()` 后 `filter`。
- **风险**：低，新增只读函数。

### P0-6 观剧照片 `src` 未转义 + 导入信任备份里的 `dataUrl`，构成存储型 XSS ✅复现

- **位置**：`观剧记录.html:365`（`'<img src="'+thumbsCache[id]+'"`，同页 `:538` 同样写法）；`:751-760` 导入时 `idbPut({..., thumb:p.dataUrl, ...})` 把备份 JSON 的 `dataUrl` **原样**存成缩略图
- **现象**：正常缩略图是本地 canvas 生成的 dataURL，但导入流程把外部 JSON 的 `dataUrl` 直接当 `thumb`；`_dataUrlToBlob` 对非 dataURL 字符串仍返回非空 Blob（`atob('')` 不抛），所以 `if(!blob) continue` 拦不住。构造 `dataUrl` 为 `x" onerror="...` 的备份文件被导入后，每次渲染记录列表都会执行脚本。
- **为什么严重**：这是 `file://` 页面，脚本可读同源 localStorage —— 任务台、明信片、海报墙、地图的全部数据都在射程内。
- **改法**：两处 `src` 套 `esc()`；导入时校验 `/^data:image\/(png|jpe?g|webp|gif);base64,/i`，不合法跳过；`thumb` 只信本地 `makeThumb()` 的产物。
- **风险**：低。转义不破坏合法 dataURL；校验可能拒绝极少数非标准图片。

### P0-7 地图「清空当前视图」只清数组不清 `litAt`，时间线继续报已清空的点亮 ✅复现

- **位置**：`旅行地图.html:1109-1114`（`clearBtn` 只 `state[childBucket()]=[]` / `state[parentBucket()]=[]` 然后 `save()`）；对照 `syncParent()` `:1023-1037` 明确在取消时 `stampLit(pp,false)` 删 `litAt`
- **现象**：`litAt` 是时间线「点亮了 X」的唯一来源（`时间线.html:619-629` 直接遍历它）。清空后地图全灭，时间线仍在报「点亮了葡萄牙」——跨页数据自相矛盾，且不可自愈。
- **附带问题**：城市视图清空时把 `parentBucket()` 也一起清空，会连带删掉用户在省份层**手动点亮**的无城市归属省份（如西藏）。
- **改法**：清空时按被清 bucket 反推唯一键（`c:`/`cc:`/`w:`/`wc:`）逐个 `delete state.litAt[k]`，不要 `state.litAt={}`（会误删另一域）；城市视图是否级联省份应显式确认。

### P0-8 地图加载失败时的降级层脱离容器、铺满视口并拦截整页点击 ✅复现

- **位置**：`旅行地图.html:837`（`mc.insertAdjacentHTML('afterbegin','<div class="map-fallback" style="position:absolute;inset:0;…z-index:2;background:var(--card)">…')`）；`#mapWrap` 只有 `overflow:hidden`、`#map` 只有 `width/height`，两者都**没有 `position`**
- **现象**：绝对定位的包含块退回视口，`inset:0` 让降级层铺满整个窗口，不透明背景 + `z-index:2` 压在导航条（z-index:1）之上 → 盖住 aside、header 与导航，点击全被吃掉。CDN 被墙、离线、key 失效都会触发。
- **为什么严重**：这正好推翻了降级层自己写的承诺「地点清单、点亮记录与日记仍可正常使用」。
- **改法**：给 `#mapWrap` 加 `position:relative`（一行），或把降级层改成流内块 `position:static;height:100%`。

## 3. P2 打磨项（打包）

**发布链/工程**
- `sw.js:51-65` 预缓存失败只 `console.warn`，`activate:66-72` 仍无条件删旧缓存 → 弱网下某页预缓存失败即永久缺页，离线兜底到 `home.html`，用户在别的 URL 上看到首页且无提示。建议失败即 `throw` 让 install 失败（浏览器会自动重试）。
- `sw.js:57` `c.add(u)` 走默认 HTTP 缓存，Pages 的 `max-age=600` 会把旧 HTML 装进新版本缓存（同文件 `:128-134` 已为导航侧规避过同一个坑）。建议 `new Request(u,{cache:"reload"})`。
- `sw.js:201` 导航 `cache:"no-store"` 让每次跳页全量重下 842KB；改 `no-cache` 可命中 ETag 拿 304。
- `sw.js` `NAV_MAP` 缺「时间线.html」，离线兜底链路里它只能退到首页。
- `verify_release.py:168-183` PRECACHE 只查「列出的存在」，不查「该列的都在」——删掉一页仍 PASS。第 3 项断言写死 `good==7` 而实际 8 页，那句 PASS 永远打不出来。
- `inject_shared.py` 非原子写（先 truncate 再写）、失败留半套；文本模式读写会把 CRLF 文件整体改成 LF。
- 观剧/地图缺 `manifest.json` 链接与 `theme-color`，从这两页「添加到主屏幕」拿不到正确名称/图标；时间线切暗色后 meta 仍是亮蓝；海报墙亮色 meta 是 `#F8FAFC` 与其它页 `#4F7CFF` 不一致，切页时状态栏跳色。

**交互/数据**
- 海报墙导出文件名用 `toISOString().slice(0,10)`（`:3887`，同页 `:3658` 已有正确写法注释）。
- 海报墙 `.toast-wrap` 引用 `var(--kb)` 但全页没人写 `--kb`（明信片有完整 `visualViewport` 逻辑），移动端键盘避让是假的。

- 地图地点日记点遮罩即关，无脏检查（观剧页有 `isDirty()`），几百字长文+已选照片一次误触全清。

- 地图仍用原生 `window.confirm`（`:1110`、`:1207`），与观剧页已全量替换的 `askConfirm` 不一致，受限 iframe 下可能静默返回 false 表现为「点了没反应」。
