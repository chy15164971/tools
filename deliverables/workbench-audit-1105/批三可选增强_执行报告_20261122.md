## 二、实际改动

### O-1 观剧记录：新增「观演日历」视图（第 5 个 tab）

补齐「剧在」类应用的时间轴视角（原只有列表 + 柱状统计）。

- HTML：`data-tab="cal"`「观演日历」，插在「数据统计」之后。
- 状态：`calY / calM / calSel`（当前年月 + 选中日期）。
- 渲染 `renderCalendar()`：
  - 7 列周网格，**周一为第一列**（`(getDay()+6)%7`），前导空格补齐；
  - `calMap()` 按 `date.slice(0,10)` 聚合，同日多场合并计数；
  - 有观演的格子加 `.has-rec` + 圆点，`is-today` 描边今天，`sel` 高亮选中；
  - 头部年月 + `‹ ›` 切换；底部「本月 N 场 · 剧历累计 N 场」；
  - 点击有记录的日期，在下方用既有 `recHtml` 渲染当日剧目，**编辑/删除按钮直接复用现有事件委托**（删除后 `renderAll()` 回到 cal 分支，日历同步刷新）。
- 无障碍：有记录的格子带 `role="button"` + `tabindex="0"` + `aria-label="YYYY-MM-DD 有 N 场观演"`，并新增 `view` 的 `keydown` 委托支持 **Enter / Space 激活**（只加 `tabindex` 不给键盘通路等于假无障碍）。
- 事件顺序：日历分支放在 `view` 点击委托**最前面**，避免与记录按钮的 `data-del`/`data-edit` 互相干扰。

### O-5 `vh` → `dvh`

- `home.html`：`min-height:100vh` → `min-height:100vh;min-height:100dvh`（保留 vh 作不支持 dvh 时的回退）。
- `媒体进度看板.html`（旧链接跳转壳）：同上。
- 五个主页面实测**已无裸 `100vh` 残留**（历史批次已完成，本轮只补剩下两处）。

### O-7 主题初值统一（本轮唯一的真实缺陷修复）

核实发现的问题比报告描述更严重：**观剧页与旅行地图页完全没有主题初始化**——两页只有 `[data-theme="dark"]` 的 CSS 变量，却从不读 `wb_theme_v1`，也没有主题按钮。后果是：用户在任务台/明信片/海报墙选了暗色，跳到观剧或地图页会**直接变回亮色**（跨页主题闪变）。

修复：
1. 观剧、地图：`<title>` 后插入首屏主题脚本，读 `wb_theme_v1`，**无显式选择时跟随系统** `prefers-color-scheme`。
2. 任务台 / 明信片：原有脚本只处理「有键则应用」，补 `else if 系统暗色 → dark`。
3. 海报墙：原脚本只在 `_wt==="dark"` 时设 `data-theme`，导致**系统暗色 + 用户显式选亮色**时首屏先渲染暗色再跳亮色；改为 `if(_wt)` 一律落 `data-theme`，并补跟随系统分支。

统一口径（六页一致）：`localStorage.wb_theme_v1` 显式值优先 → 无值则跟随系统 → 都没有则 CSS 默认亮色。

### O-1 附带修正：日历配色对比度

初次实现用了 `--pri-deep`（主色）作为日历文字色。真浏览器实测发现两套主题均不达 WCAG AA：

| 位置 | 原配色 | 实测对比度 | 修正后 | 实测 |
|---|---|---:|---|---:|
| 有记录格（亮色） | `--pri-deep` on `--pri-soft` | 4.15:1 ✗ | `--pri-ink` | **4.80:1** ✓ |
| 有记录格（暗色） | `--pri-deep` on `--pri-soft` | 3.14:1 ✗ | `--pri-ink` | **6.68:1** ✓ |
| 本月场次数字（亮色） | `--pri-deep` on card | 4.73:1 边缘 | `--pri-ink` | **5.48:1** ✓ |
| 本月场次数字（暗色） | `--pri-deep` on card | 3.95:1 ✗ | `--pri-ink` | **7.63:1** ✓ |

项目 `design_tokens.css` 本就为此定义了 `--pri-ink`（「主色当文字用」，亮 5.48:1 / 暗 8.4:1），本轮改为遵循该约定。

## 四、明确不做的三项及理由

### O-4 PWA 预缓存 TMap GL JS — 不做

- TMap 的 key 鉴权与瓦片请求**必须联网**。把 `map.qq.com` 的脚本缓存进 PRECACHE，离线时脚本能跑、地图仍是空白，**不能实现「离线看地图」**，只能省一次 CDN 请求。
- 跨域脚本在 Cache API 里是 `opaque` 响应（`response.ok === false`），要入库必须放宽 SW 的成功判定，等于把 `install` 的失败面扩大。
- 已有更合适的替代：`MAP_OK` 守卫 + CDN `onerror` + 降级提示（批一 M-1），离线时清单与日记照常可用。
- 结论：**收益小于风险，维持现状**。

### O-6 死代码清理 — 不做

- `iconify()` / `EMOJI_ICON` 确实当前无渲染路径调用，但页面注释（明信片 1950–1954 行）已明确它是**统一维护的图标层**，并写明调用约定「需要图标化时请显式写 `iconify(esc(x))`」。删掉会让这条约定失效，且函数体删除会触发 P1-9 守卫 G4/G5/G9 重冻——为「干净」换一次结构基线重冻不划算。
- 跳转壳 `媒体进度看板.html` 的三重跳转不是冗余：`meta refresh` 在**禁用 JS** 时是唯一跳转手段，`location.replace` 是正常路径，`noscript` 链接是最后兜底。属渐进增强，保留。

### O-2 / O-3 / O-8 — 已实现，只做守卫

见第一节表格。这三项在本轮不做功能改动，改为在专项测试里加**防回退断言**（O2-1/O2-2、O3-1/O3-2/O3-3、O8-1/O8-2），以后谁改坏了会直接报红。

## 五、期间发现并修复的测试脆弱性

三个验收测试（`观剧记录.验收测试.mjs`、`旅行地图_城市版.验收测试.mjs`、`旅行地图_地点日记.验收测试.mjs`）都用

```js
const m = html.match(/<script>([\s\S]*?)<\/script>/);   // 取「第一个」script 块
```

定位主逻辑。O-7 在观剧/地图的 `<head>` 里新增主题初始化脚本后，第一个 `<script>` 变成了那个小脚本 → 三个测试同时报 `ReferenceError: KEY is not defined`（门禁 3 FAIL）。

修复：改为按特征定位

```js
const _blocks = [...html.matchAll(/<script>([\s\S]*?)<\/script>/g)].map(x => x[1]);
const code = _blocks.find(b => /const\s+KEY\s*=/.test(b));
```

这是**修复测试的脆弱假设**，不是放宽断言：三个测试的断言内容一字未改，修复后 `32 / 74 / 28 PASS / 0 FAIL`，与改动前完全一致。

## 六、诚实披露

1. **审查报告的 O 项有 5 项与现状不符**（O-2/O-3/O-8 已实现、O-4 收益为负、O-6 属合理设计）。批三实际只做了 2 项新增 + 1 项缺陷修复。这不是缩水，是核实后的取舍，理由已逐项记录在本文第一、四节。
2. **O-7 的「跟随系统」用 `--color-scheme dark` 启动参数验证**（六页 `data-theme=dark` + 暗色变量生效）。本轮也发现 `agent-browser media dark` 命令**静默无效**（`matchMedia` 仍返回 `light`），与历史记录的 CLI 缺陷一致，故改用启动参数。
3. **暗色对比度是实测计算值**（页面内 `getComputedStyle` 取色后按 WCAG 相对亮度公式计算），不是视觉估计。
4. **日历未做「跨年跳转/年度热力图/连续观演 streak」**——审查报告 O-1 原文只要求「日历呈现观演日期、场次密度、连续观演记录」，本轮做了日期与场次（每日圆点 + 当日列表 + 本月合计），**未做 streak 与年度热力图**，如需可另列增强。
5. 五个 tab 在 390px 下需要横向滚动约 36px（`.tabs` 本就是 `overflow-x:auto`）。未强压字号/内边距换取「刚好放下」，因为那会牺牲桌面端可读性。
6. O-9 的拆分成本判断基于代码规模与工具链实测，**未做构建化迁移的 POC 计时**。
