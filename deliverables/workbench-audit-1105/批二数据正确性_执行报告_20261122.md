## 一、五条改动

### P1-1 快速添加「每周三」丢掉星期

- **位置**：`任务管理台.html:4227`（`parseNL`）、`:4818`（`recLabel`）、`:10784`（弹窗「识别」回填）
- **成因**：`parseNL` 产出 `{freq:"weekly", day:3}`，而 `recMatch`(:3921) 与 `recLabel` 只读 `daysOfWeek`，缺省各自回退成「baseStart 的星期」「今天的星期」。弹窗路径写的是 `daysOfWeek` → 同一句话两条录入路径结果不一致。
- **改法**：`parseNL` 统一产出 `daysOfWeek:[d]`；`recLabel(rec, baseStart)` 增加起算日参数，缺 `daysOfWeek` 时按**起算日**的星期显示（与 `recMatch` 兜底同口径），并把两处调用点补上 `t.start`。
- **附带修掉**：旧 `recLabel` 回退表达式是 `"周"+(new Date().getDay())`，老数据会渲染出「每周 周0」——改前对照里 A8 就是这条。

### P1-9 云合并：云端任务命中本地墓碑就丢弃

- **位置**：`任务管理台.html:11321`（`mergeTasks`）
- **成因**：同函数本地分支按 `updated` 与墓碑 `ts` 裁决，云端分支却是 `if(!t||del.has(t.id)) return;` → **A 删 T、B 随后编辑 T** 时互相抵消：A 永远看不到 T、B 永远删不掉 T，每次同步互相覆盖一次。
- **改法**：抽出 `aliveByTomb(t, dts)` 作为**唯一判据**，本地/云端两侧都调：
  - `ts>0` → `updated > ts` 才算活（删除后又被编辑 ⇒ 复活）；
  - `ts==0` → 旧格式墓碑没有时刻可比，只删「从未被编辑过」的任务。
  - 任务活着就 `del.delete(id)`：此前只有 `ts===0` 才撤墓碑，`ts>0` 的任务即使活着墓碑也会被写回 `deletedIds` 一路传下去。

### P1-10 补打卡「仅目标日」拿本周日期去和历史区间求交集

- **位置**：`任务管理台.html:5471`（新增 `habitTargetDaysInRange`）、`:7128`（`confirmHabitBackfill`）
- **成因**：`habitWeekTargetDays` 只推导**当前自然周**；周一打开补打卡时默认区间（`today-5 ~ today-1`）整段落在上一周 → 交集恒空 → 明明一天没打却提示「所选日期均已打卡」。
- **改法**：新增 `habitTargetDaysInRange(h, d0, d1)` 在给定区间内推导——daily=每天 / weekly=每自然周前 N 天（周一=0，与「本周目标日」同口径）/ custom=勾选星期 / someday=空。`habitWeekTargetDays` 原样保留给「本周目标日」「本周全完成」这类真正按周的功能。

### P1-11 单向代寄的往返节点日期不在脏检查字段里

- **位置**：`明信片追踪.html:5249`（`PROXY_FORM_IDS`）
- **成因**：缺 `pEnvSent`/`pEnvRecv`/`pProxyMode`，而 `saveProxyModal` 会写 `envSent`/`envRecv`/`proxyMode`。单向代寄最典型的操作恰好是「只填一两个往返节点日期」。
- **改法**：三个 id 补进快照表（15 → 17 项）。已确认 `proxySnapshot` 是在 `applyProxyModeUI` 与全部取值**之后**才记录，所以打开弹窗不会误判「已修改」。

### P1-2 今日页逾期 14 天窗口外没有出口

- **位置**：`任务管理台.html:4669`（常量）、`:4693`（模型）、`:4706`（计数）、`:4729`（渲染）、`:4736`（绑定）、`:277`（CSS）、`:7673`（分区末尾）
- **成因**：`buildTodayModel` 只展开 `[d0-14, d0]`；顶部「逾期」功能卡走 `collectOverdueSet`（非重复不限窗口）→ 两个数字当场矛盾，用户以为任务丢了。
- **改法**：窗口常量收敛为 `TODAY_BACKLOG_DAYS=14`（此前 -14 写死两处），新增：
  - `countOlderOverdue(d0, shownIds)`：任务级去重，非重复看 `end < 窗口起点`，重复在 90 天视野内找未完成实例（与 `collectOverdueSet` 同区间 ⇒ `getInstances` 记忆化命中，不额外付出展开成本）；排除已完成 / 不补做 / `skipMissed` / 已在窗口内展示过的任务。
  - 今日页底部一行「还有 N 项更早逾期 · 去回顾查看」（`.today-more`，虚线分隔、`focus-visible` 描边、按钮 32px 高），空态也渲染。

## 二、踩到的坑（已固化为断言）

**切视图不能调 `go()`。** 初版写 `b.onclick=()=>go(VIEWS.REVIEW)`，而 `go` 是 `CmdPalette` IIFE 内的**私有函数**（`任务管理台.html:12238`，不在全局）。静态断言、`node --check` 全绿，真浏览器点击直接 `ReferenceError`、状态不变。

- 现改为 `state.view=VIEWS.REVIEW; syncSeg&&syncSeg(); renderAll();`
- 新增 **E12 点击行为断言**：jsdom 里真点一次，断言 `state.view==='review'` 且 `#view .today-page` 消失。
- **反向验证**：把固定写法改回 `go(VIEWS.REVIEW)` 跑同一套 → **只有 E5/E12 变红**（35 PASS / 2 FAIL），证明这两条专治该回归。
- 附带教训：`renderAll()` 用 `_raPending` + `queueMicrotask` 合并重绘，**同一个同步块里连续两次 renderAll 的第二次会被吞掉**。E12 里显式调 `renderAllNow()` 绕过锁，等价「用户点击后的下一帧」。
