# 时间线功能（第八页）· 执行报告

日期：2026-11-22　版本：`APP_CACHE = wb-app-v26`

## 一、需求

> 我想再增加一个时间线功能，参考现在的时间线 app，就是把各个页面不同的事件按照时间线串联起来。

工作台此前是七个页面各自独立的记录视图：任务台管待办与习惯、明信片管寄收、海报墙管书影音、观剧管现场、地图管足迹。没有任何一处能回答「我这半年都干了什么」。本次新增第八页「时间线」，把这些分散的事件按时间合并成一条竖轴。

## 二、设计取舍

### 2.1 只读聚合，不新增业务数据

时间线页**不写任何业务数据键**，只读各页已有的 localStorage 与 IndexedDB。理由：

- 各页已有各自的云同步、墓碑仲裁、合并逻辑（任务台 9 类集合并集、海报墙 ts 仲裁、明信片 tombMap）。若时间线再存一份副本，就会出现第三套需要仲裁的数据，一旦不同步就是「时间线显示了任务台已删除的记录」这类脏数据。
- 只读意味着时间线页**永远不可能导致其他页数据损坏**，零同步风险。
- 页面上显式标注「本页只读，不修改任何页面的数据」，用户可核对。

唯一写入的键是主题偏好 `wb_theme_v1`（与其余七页共用）。

### 2.2 解析层抽成唯一真相源

新增 `_shared/timeline-core.js`，通过 `inject_shared.py` 内联进**时间线页与首页**。

原因：首页第六张卡要显示「本年事件数」，时间线页要渲染完整事件流。若两处各写一套解析，某页字段微调后就会出现「首页说 120 件、时间线只有 98 件」的口径分叉。项目既有铁律是「唯一真相源 + 注入」，此处沿用。

由此共享内联块从 21 块增至 **25 块**（SHARED×3 + SITE-NAV-HTML×8 + SITE-NAV×8 + MODAL-A11Y×4 + TIMELINE-CORE×2），`verify_release.py` 的计数断言同步更新。

## 三、事件来源与精度

| 来源 | 数据键 | 事件 | 精度 |
|---|---|---|---|
| 任务台 | `wb_taskhub_v1` → `doneAt` | 完成某任务（重复任务每次实例各一条） | 分钟级 |
| 任务台 | `wb_taskhub_v1` → `doneDates` | 老数据兜底（仅当该日无 `doneAt`） | 日级 |
| 任务台 | `wb_taskhub_habits_v1` → `days`/`dayTs` | 习惯打卡 | 当日打卡为分钟级，补打卡为日级 |
| 明信片 | `wb_postcards_v1` | 寄出 / 抵达 / 收到 | **仅日级**（只有日期字段） |
| 海报墙 | `wb_mediawall_reviews_v1` | 写了感想 | 分钟级 |
| 观剧 | `wb_theatre_v1` | 现场观演 | 日级 |
| 地图 | `wb_travel_map_v1` → `litAt` | 点亮国家/城市 | 分钟级（v26 起才有） |
| 地图 | IndexedDB `wb_travel_diary_db` | 旅行日记 | 日级 |

### 三点必须说清的限制

1. **明信片、观剧、旅行日记只有日期没有时刻**。时间线不编造时刻：这类事件显示 `11-20` 而非 `11-20 00:00`，并在排序上固定排在当日所有精确事件**之后**（不是「凌晨发生」）。
2. **地图点亮此前无时间戳**。v20 上线时 `state` 只存布尔点亮状态，本次补记 `litAt`（见第四节），因此**2026-11-22 之前的点亮无法追溯**，不会出现在时间线里。页脚已注明。
3. **补打卡不冒充打卡时刻**。`dayTs` 记的是「操作那一刻」，若与补的日期不是同一天（补打历史），按日级处理，时刻取补的那一天零点。

## 四、地图点亮补记 `litAt`

`旅行地图.html`：

```js
litAt: { 'w:pt': { t: 毫秒, n: '葡萄牙' } }   // 键 = 带表前缀的唯一键 k
```

- 值里存**地名**，这样时间线页不必加载 550 条地名表也能显示「点亮了葡萄牙」。
- 城市点亮导致省份**合成**点亮时**不写** `litAt`——用户点的是城市，给省份伪造时刻会让时间线出现他没做过的动作。
- 反过来，取消最后一个城市导致省份连带撤销时，必须**同时删** `litAt['c:xx']`，否则时间线会留一条「点亮过广东」而地图上广东已经不亮。
- 旧数据无 `litAt` 字段时按空对象处理，字段缺失不报错、不伪造。

字段用带前缀的 `k`（`c:`省 / `cc:`中国城 / `w:`国 / `wc:`世界城）而非裸 id —— 这是 v25 修的 33 处 id 撞车问题的延续：`gd` 既是广东也是格林纳达，`es` 既是恩施也是西班牙。测试时我自己就踩了一次（在世界域点 `gd` 点亮了格林纳达）。

## 五、页面能力

- **统计条**：合计 / 今年 / 本月 / 最早记录，随筛选实时变化（选「观剧」看的就是观剧的年度分布）。
- **来源筛选**：全部 + 七类，每个 chip 带条数。
- **关键词搜索**：标题与副行。
- **年份筛选**：从现有事件动态生成，不硬编码。
- **竖轴 + 年月分组**：月份标题 sticky 吸附；年份节点用大圆点。
- **分批渲染**：首次 300 条，超出显示「再显示 300 条」。
- **空态分两种**：全无数据时给「去哪几个页面记一笔」的引导；筛选无结果时提示换条件。
- **对比度**：亮/暗两套实测全部 ≥4.5:1（见第七节）。

## 八、已知限制（诚实披露）

1. **跨域读不到**：数据存在同一浏览器同一站点下。换浏览器、换域名、无痕窗口都读不到其他页的数据。file:// 双击打开时各页共享同一 `file://` 源的存储（Chrome 实测），但不同浏览器行为不一致。
2. **2026-11-22 之前的点亮不可追溯**：`litAt` 是本次新增，历史点亮只有布尔状态。不伪造时刻。
3. **日志按需读取**：旅行日记在 IndexedDB，时间线页用 `indexedDB.databases()` 做只读探测。**不支持该 API 的浏览器不读日记**（只显示提示），因为裸 `open` 会在库不存在时建出空库，导致地图页之后同版本 open 不再触发 `upgradeneeded`、store 永久建不起来——这是必须规避的破坏性副作用。
4. **海报墙「已看 / 想加」动作本身不产生事件**：该页只对「写了感想」记录 `ts`，标记看过的时刻没有落盘。要补需要改海报墙写入（561KB / 1731 条数据），本次未做。
5. **不是实时同步**：页面加载时读取一次快照。在其他页产生记录后，回到时间线点「重新读取」才会更新。
6. **不做「那年今日」「热力图」**：这两个视图需要额外的时间分桶计算，且与现有统计条信息重叠，本次未纳入。
