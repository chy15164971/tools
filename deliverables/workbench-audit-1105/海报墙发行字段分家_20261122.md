# 海报墙时间字段分家：`date`（我的完成）vs `release`（作品发行）

**版本** v28 · **日期** 2026-11-22 · **触发** 用户「帮我修吧」（v27 遗留的统计口径失真）

---

## 一、为什么要修

v27 只改了弹窗文案，数据层还留着一个结构性错误：**同一个 `date` 字段承担了两种互相矛盾的含义**。

- 书本的 `date` = 豆瓣「读过」标记日期 → 我什么时候读完
- 内置影音的 `date` = 豆瓣「上映/出版日期」 → 作品什么时候出的

于是所有 `date` 的消费者都在拿「2010 年上映了多少部电影」当「2010 年看完了多少作品」算：

| 位置 | 旧行为（错） | 影响量级 |
|---|---|---|
| 分析页「完成年份分布」 | 书本 + 影音混算 | 1721 条里 1377 条是发行年份 |
| 分析页「月度消费节奏」 | 含影音发行月份 | 同上 |
| 分组卡片「最近完成」 | 三个分组统一写「最近完成」，影音那栏其实是发行年 | 已看 995 / 已听 391 |
| 兴趣画像「近期权重」 | 影音按**上映年份**算「近 12 个月升温 ×1.5」 | 影响画像排序 |
| 排序「最近完成」 | 发行月份与读完日期混排 | 全墙 |
| 详情弹窗 | 按 `type` 猜语义：非书本一律「发行于」 | 自建的电影条目会被说成「发行于」 |

---

## 二、做法：字段分家

### 2.1 数据迁移（一次性，1731 条）

内置影音的 1377 条 `date` 改名为 `release`，键名原地替换、其余字段逐条校验一致：

```
迁移前：date 1721 条（影音 1377 + 书本 344）、无 date 10 条
迁移后：date   344 条（全部书本，全部 YYYY-MM-DD）
        release 1377 条（全部影音，YYYY / YYYY-MM）
        两者皆无 10 条（9 条音乐 + 「未知图书」，豆瓣导出本来就没日期）
```

字段语义从此写进数据块头部注释：`date` = 我完成的日期，`release` = 作品上映/发行日期。

### 2.2 六个消费者改口径

| 位置 | v28 |
|---|---|
| 完成年份分布 | 只算 `date`（344 条真实读完 + 自建条目），标题带覆盖数说明 |
| 影音发行年代（**新增**） | 只算 `release`（1377 条），标题写「按作品上映 / 发行年份，**不是观看时间**」 |
| 月度完成节奏（原「月度消费节奏」） | 只算 `date` |
| 分组卡片 | 有 `date` 说「最近完成」，只有 `release` 说「最近发行」，都没有说「时间未记录」 |
| 兴趣画像近期权重 | 只认 `date`；影音不再被抬成「兴趣升温」 |
| 排序 | 更名「最近完成 / 发行」，`date` → `release` → `year` 三级，缺失值沉底 |
| 详情弹窗 | 按字段判：内置影音「发行于」+ 书本「读完于」/ 自建条目「完成于」；发行月份已含年份时不再重复显示「年份」行 |

### 2.3 顺带修的一处自相矛盾

新增/编辑表单的「完成日期」输入框原本是 `type="month"`（只能选到月），而「标记为已完成」那条路径已经写日级日期。既然日期本身就是精确到天的事实，改成 `type="date"`。

## 四、诚实披露

1. **影音仍然没有观看时间。** 豆瓣导出的「标记日期」列对电影/音乐整列为空，这不是本轮能补的。所以时间线里依然只有书本「读完了」，`wb_mediawall_readlog_v1` 索引（343 条）与 `timeline-core` 的 4b/4c 逻辑一个字没改。
2. **曲线会明显变化，这是预期。** 「完成年份分布」从 1721 条降到 344 条，颜色只剩「读书」一种主导分区；「月度消费节奏」改名「月度完成节奏」后每月数量大幅下降。旧图好看是因为把发行年份当成了观看年份。
3. **66 条影音日期的来源无法逐条核实。** 它们的 `release` 在豆瓣导出里「发行/出版日期」为空（如《浮躁》1996、《爱你》2004），值来自当初导入时的兜底取值。我按「同一个导入管道的产物、语义同样是作品年份」整体迁移，没有单独特判——但也不能证明每一条都精确。
4. **E2E 脚本改判据，不是放宽标准。** `type="date"` 在 Chromium 里有 3 个内部可聚焦分段（日/月/年），而 `focus_trap_e2e.py` 用 `querySelectorAll('*')` 数不到 shadow 分段，`n+2` 少算 3 步导致「本来正常回环」被判 FAIL（实测 formMask 一圈 17 步、n=13）。改为「Tab 到回到起点为止，上限 n+10」，回环性质与「焦点不出弹窗」两条断言都保留。
