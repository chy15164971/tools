# 海报墙「看过 / 想看」时间戳 + 时间线接入（v27，2026-11-22）

> 触发：用户「给海报墙的看过/想看补时间戳，可以根据我之前提供的文件补时间戳吗」
> 随后提供了三份豆瓣导出 CSV：`douban-book/movie/music-collect-20260714.csv`（`/Volumes/My Passport/待整理/`）
> 决策：独立提议的两个岔口由用户选定——①「我重新发给你」（等文件回填）；②时间线「都收，完成默认关闭」。

---

## 一、先说结论：三份文件能给什么、不能给什么

用 `csv.DictReader` 全量核对（书 345 行 / 影 995 / 音 395，共 1735 行；MEDIA 现有 1731 条）：

| 事实 | 数据 | 后果 |
|---|---|---|
| 书本「标记日期」**有**真实日期 | 344/345 行形如 `2009/06/07 读过` | ✅ 可把 `date` 从「月」补到「日」，这是真·时间戳 |
| 电影「标记日期」**全为空** | 0/995 | ❌ 没有任何观看时间可补 |
| 音乐「标记日期」**全为空** | 0/395 | ❌ 同上 |
| 影音现有的 `date` 其实是**上映/发行日期** | 与「发行/出版日期」月份一致：影 954 + 音 335 = 1289 条 | ⚠️ 之前弹窗写「完成于」，等于把发行年月说成看完时间 |
| 「想看 / 想读 / 想听」条目 | **0 条**（三份全是 看过/读过/听过） | ❌ 心愿单时间无法从文件回填，只能从现在起记 |

也就是说：**「看过」的时间一直就在页面里**（1721 条有 `date`），只是精度到月；**「想看」从来没有过时间**——
心愿单只能是页面里手动新增的条目，而旧代码在标记心愿单时会显式 `delete entry.date`。

## 二、做了什么

### 1. 数据：书本 date 补到日级（344 条）

- 依据豆瓣「读过」标记日期，把 `书本` 的 `date` 由 `YYYY-MM` 改为 `YYYY-MM-DD`。
- 同书多版本（`海底两万里` / `呼啸山庄` / `老人与海` / `你好，旧时光` / `红楼梦脂评汇校本`，共 5 组 6 行）
  **取与原月份一致的那条**：只补日、不改月，零口径变更。
- `未知图书` 导出里也没有日期 → 保持空，不编造。
- 改后校验：书本 344 条 `YYYY-MM-DD`、0 条月级、1 条无日期；条目总数仍 1731；除 `date` 外无任何字段变动。

### 2. 影音：不补假时间，只把话说明白

- 数据不动（`date` 仍是发行/上映日期），但详情弹窗按类型分开口径：
  - 书本 → **读完于** `2009-06-07`
  - 电影 / 音乐 / 电视剧 / 真人秀 → **发行于** `2010-10`（原来一律写「完成于」）
- 分析页两处口径加诚实说明：完成年份「书本按豆瓣读过日期；影音是发行年份（导出里没有观看时间）」、
  月度节奏「影音按发行月份」。
- 统计逻辑**未改动**（完成年份 / 月度节奏 / 最近完成仍按 `date` 过滤），避免一次改两件事；
  影音对该三项统计仍是失真的，见「四、还没做的」。

### 3. 心愿单：从今天起记 `wishAt`

- 新增条目选「心愿单」时写入 `wishAt = Date.now()`（毫秒）；标记为已完成时**保留** `wishAt`——
  它是历史，不是状态。
- 标记完成时 `date` 由「只到月」改为**精确到日**（「刚刚标记」本来就是分钟级的，写到月是白丢精度；
  既有消费者全走 `slice(0,4)/slice(0,7)/^YYYY-MM`，多出来的日对它们无影响）。
- 弹窗新增一行：`加入心愿单 2026-11-22 11:58`；达成后变成
  `加入心愿单 2026-11-02 · 心愿单里待了 20 天`（同日显示「当天完成」）；
  旧条目没有 `wishAt` 时如实写「时间未记录」，不拿别的日期冒充。
- 云同步无需改动：`syncPayload()` 直接同步整个 `entries`，新字段自然带上。

### 4. 时间线：新增第七类来源的两个事件

- 新增 `wb_mediawall_readlog_v1`（**只读索引**，由海报墙页单点写、时间线只读）：
  只收「书本 + 合法日期」，影音一条不收。同书名同日期的重复条目并掉
  （`红楼梦脂评汇校本` 导入两次），保证开关上的条数 = 时间线上实际出现的事件数 → **343 条**。
- `timeline-core.js` 新增：`4b` 心愿单加入（`wishAt`，精确到分）、`4c` 读完了（`withDone` 开关控制）。
- 事件模型加了 `variant`（review / wish / done）与 `lvl`（min / day / month / year），
  时间戳文案严格跟随精度：`11-22 11:58` / `7-09` / `2010-10` / `2015`。
- 时间线页新增一行开关「☑ 含历史「读完了」343 条」，**默认不勾**；没有索引时置灰并说明
  「打开一次海报墙页就会生成」。页脚补了三条诚实边界（心愿单时刻起点、读完默认不计入、影音没有观看时间）。

## 四、还没做的（需要你决定）

1. **影音的「完成年份 / 月度节奏 / 最近完成」统计仍然失真**——它们按 `date` 算，而影音的 `date` 是发行日期。
   彻底修需要把影音的 `date` 迁移成 `release` 字段并重算这三项，会让人看到的"完成年份"曲线明显变化，
   所以这次只改了文案与时间线口径，没有动数据与统计。
2. **心愿单历史时间补不了**：三份导出里没有任何「想看」条目。若你在豆瓣还有「想看」列表的导出
   （或截图/清单），可以按标题 + 日期补 `wishAt`——海报墙页本身有「⬆ 导入」入口，也可以走那条路。
3. 影音若真想要「看完时间」，只能从现在起：看完一部就在海报墙把「标记为已完成」或新增条目填日期。

## 五、可逆性

- 改前五文件备份 + SHA256：`_ops/_整理记录/海报墙时间戳_备份_20261122/`
  （`书影音海报墙.html` / `时间线.html` / `home.html` / `sw.js` / `timeline-core.js`）。
- 数据订正可逆：书本 date 的改写仅是把 `YYYY-MM` 截成 `YYYY-MM-DD` 的前 7 位即可还原。
- 时间线只读：`wb_mediawall_readlog_v1` 删掉即回到「没有这份索引」的降级态，不影响海报墙自身数据。
