# 补记时刻校准 · 执行报告（2026-11-22）

## 背景与决策

用户反馈：任务台大量习惯打卡与任务完成是**事后补记**的，分钟时刻不精准。诊断结论：

- **日期层全程是准的**：连续天数、周达标、月度趋势、统计报表全部按「日期」计算，补卡时日期落在真实发生日——这部分从未出错。
- **只有分钟级时刻不准**：任务补完成记「该日 + 补操作那一刻的钟点」；习惯 `dayTs` 直接记补操作时刻，且无修改入口。
- 技术约束：习惯 `dayTs` 兼任云端合并的**墓碑仲裁**（必须记真实操作时刻，否则「删了又重打」会被旧墓碑回滚，死锁复现），不能直接改成编造的时刻——显示层校准必须与仲裁时刻解耦。

用户从四个方案（A 诚实降级 / B+A 补卡可选时刻 / C=B+A 存量校准工具 / D 不改）中拍板 **C 完整方案**。

## 实施内容

### 1. 任务补记打标 `doneBf`（诚实降级）

- `toggleDone` 两个补打卡分支（非重复 / 重复任务）在 `date≠today` 时写 `t.doneBf[key]=1`（key 与 doneAt 同构：普通任务 `"self"`、重复任务=发生日）。
- `setDoneAt` 删除分支统一清标（取消完成的唯一出口不残留）；`applyDoneTime` 三处（rec 迁移旧 key / rec 新 key / 非 rec self）在用户显式确认时刻时清标——改过时刻视为「我确认这是真实时刻」。
- 新增 helper `markDoneBf` / `clearDoneBf`。

### 2. 习惯显示时刻 `dayTime`（与仲裁解耦）

- 新字段 `h.dayTime[d]="HH:MM"`：只作时间线显示，`dayTs` 保持 `Date.now()` 兼任墓碑仲裁——两者职责分离，互不污染。
- 批量补卡弹窗新增可选「打卡时刻」输入（`bfTime`，仅补打模式显示）：填了 → 写 `dayTime` 精确显示；不填 → 时间线按日期诚实降级（提示语：不确定真实时刻就留空，诚实优于编造）。
- 四处取消打卡路径（批量取消 / 补卡弹窗 remove / 单格 toggleHabitDay / 本周清空）同步删 `dayTime`。

### 3. timeline-core 消费端

- task 侧：`doneBf[key]` 存在 → `precise=false`（只显示日期），否则按原 `hasTime(raw)`。
- habit 侧：`dayTime[d]` 为合法 HH:MM → `base + 时刻` 且 `precise=true`；否则维持既有 `sameDay(dayTs, base)` 启发式降级。
- 注入时间线页 + 首页（`inject_shared.py` 重跑，2 页有改动）。

### 4. 存量校准工具

- 入口：习惯视图工具栏「🧹 校准时刻」按钮 → 独立弹窗。
- 嫌疑识别（双口径）：
  - 习惯：`dayTs[d]` 的日期 ≠ `d`（补操作跨日）——实时打卡不误报。
  - 任务：`stats.history` 条目的 `ts` 日期 ≠ 发生日 `d`（同一 id+发生日去重取最近），反查 `doneAt`（重复任务 key=发生日 / 普通任务 key=`"self"`），已被取消的跳过。history 触顶丢弃（`historyDropped`）的旧记录无法识别，如实不列。
- 处置：统一校准为可配置默认时刻（默认 21:00），清单勾选式预览（默认全选），`confirmDialog` 确认后应用。
- 可撤销：应用前把受影响字段深拷贝快照到 `localStorage wb_taskhub_cal_backup_v1`，「撤销上次校准」整体还原 `dayTime`/`doneAt`/`doneBf`。
- 已接入 Escape 关闭链（与六个批三弹窗同口径）。
