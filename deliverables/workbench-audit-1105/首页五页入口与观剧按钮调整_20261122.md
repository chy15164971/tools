## 一、观剧页「‹ 海报墙」按钮移除

### 位置与判断

观剧页头部原有一枚 `<a class="btn" href="书影音海报墙.html">‹ 海报墙</a>`（v19 上线时加的「返回上一级」入口）。它与站点一级导航条里的「海报墙」链接**功能完全重复**，且是二级返回语义，放在一级页面的操作按钮区确实别扭——用户判断准确。

### 处置

删除该按钮，头部只保留四个真实操作：`+ 记一场` / `+ 想看` / `导出备份` / `导入恢复`。

**不造成断路**（已双向核实）：
- 导航条「海报墙」链接仍在（`data-page="media"`）；
- 海报墙侧通往观剧的入口仍在（`sib-link`「🎭 观剧记录」+ 导航条「观剧」）；
- 观剧页当前页高亮仍正确指向「观剧」。

## 二、首页更新：它停在「三页时代」

### 发现的问题

首页 `home.html` 自建成起只在任务台/明信片/海报墙三页时代维护过。观剧记录（v19 上线）与旅行地图（v20 上线）**始终没有首页入口**，用户只能靠顶部导航条进入。具体陈旧点：

| 位置 | 改前 | 问题 |
|---|---|---|
| `<title>` | 工作台 · 任务台 / 明信片 / 书影音海报墙 | 漏两页 |
| 副标题 | 「三个页面共用一个入口」 | 与实际五页不符 |
| 卡片组 | 3 张 | 缺观剧、地图 |
| 概览区 | 4 格（合计/任务/明信片/媒体） | 缺观剧、地图 |
| 概览合计 | 「三个页面已保存的记录总数」 | 口径陈旧 |
| 数据说明 | 未提观剧与地图的存储边界 | 缺诚实披露 |

### 改动

**1. 卡片 3 → 5**

| 卡片 | 指标 |
|---|---|
| 观剧记录（新增） | 观演场次 / 想看 / 去过的城市 |
| 旅行地图（新增） | 中国省份 / 中国城市 / 世界足迹 |

指标全部读真实 localStorage，不做估算、不新增存储键。

**2. 布局方案**

`.grid` 由 `repeat(3,1fr)` 改 **6 栏基座**：

```
前 3 张 .card      → grid-column: span 2  （一行三张，399px）
后 2 张 .card.wide → grid-column: span 3  （一行两张，607px）
```

用显式 `.wide` 类而非 `:nth-child`，卡片顺序调整不会破版。断点：
- 820px：跨度重置为 auto，第 5 张整行；
- 560px：单列。

同时删除三卡时代的遗留规则 `.grid .card:nth-child(3){grid-column:1/-1}`。

**3. 概览 4 → 6 格**

`repeat(3,1fr)` 两行；新增「观剧数据状态」「地图点亮状态」；合计改为五项之和。
地图副行单独用「已点亮 · 共 N 处」而不是「条」——地图是点亮语义，用「条」不准确。

**4. 数据口径**

```js
// 观剧：城市按记录 city 去重，空白不计
// 地图：世界足迹 = worldCountries + world（二级结构，同一地点只记在对应层级）
```

`renderOverview` 签名由 `(t,p,m,keepTime)` 扩为 `(t,p,m,th,mp,keepTime)`，`keepTime` 仍在末位，`render(true)`（媒体兜底抓取）不被破坏。

**5. 文案与披露**

- 标题/副标题/概览说明统一五页口径；
- 数据说明补一句「观剧记录与旅行地图目前只存本机，不走 Gist」——这两页确实只存 localStorage/IndexedDB，原文案说「各页数据仍由页面自身与 GitHub Gist 云同步管理」对它们是失真的。

**6. 顺带修的既有缺陷：图标对比度**

五卡并排后实测发现老三个图标亮色前景不达 AA，且与新卡深浅不一：

| 图标 | 改前 | 改后 |
|---|---|---|
| 任务台 ✓ | `#3D68F0` → 4.15:1 | `#2F5FE0` → **4.80:1** |
| 明信片 ✉ | `#d4537e` → 3.41:1 | `#b23c62` → **4.91:1** |
| 海报墙 ▦ | `#8b5cf6` → 3.61:1 | `#6d3fd6` → **5.37:1** |

暗色原本 6.53–8.13 全部达标，未动。图标是装饰性元素（卡片另有 h2 标题），严格说不受 WCAG 文本对比度约束，但五卡并排时深浅不一致本身就是视觉瑕疵。

## 四、诚实披露

1. **地图「点亮数」与地点日记不一致**：概览与卡片读的是 `wb_travel_map_v1` 的点亮状态；日记本身在 IndexedDB，未计入。已在页面 `ov-note` 明确写出，避免用户以为数字漏了。
2. **观剧「去过的城市」依赖用户填城市字段**：记录里城市留空的不计入（本次造数专门覆盖了这种记录）。这是口径选择，不是缺陷；若用户希望按剧院名去重可再调。
3. **首页仍不主动写任何业务数据**：不动 localStorage 业务键，只读摘要，与原设计一致。
4. **地图世界足迹是「国家 + 城市」合数**：地图是二级结构，同一地点只记在一层，相加不会重复计数；但用户若在东三省层面点亮国家又叫不出具体城市，数字语义偏向"足迹条数"而非"去了几个地方"。已在卡片标签用「世界足迹」而非「世界城市」规避误导。
5. **未做**：`fetch` 兜底只服务媒体计数（海报墙页面内嵌数据），观剧/地图数据都在 localStorage，无需网络抓取，故未扩展兜底逻辑。
